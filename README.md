# fuan-map

福安宮廟地圖的靜態網頁與資料。

## 宮廟資料範圍

截至 2026-09-20，地圖共有 **309 筆**：臺北市 12 筆、新北市 3 筆、桃園市 294 筆。
目前尚未涵蓋全台；桃園資料涵蓋 13 個行政區，並非桃園所有實際存在的宮廟。

- `data/temples.json`：地圖優先載入的主要資料。
- `temples.js`：JSON 載入失敗時的備援，宮廟與需求對照內容須與 JSON 一致。
- `data/taoyuan-import-report.json`：桃園資料來源、各區筆數、24 筆待補座標資料及欄位問題。

桃園資料來自內政部宗教及禮制司的[全國宗教資訊系統資料－寺廟](https://data.gov.tw/dataset/8203)，
於 2026-09-20 取得[官方 XML](https://religion.moi.gov.tw/Report/temple.xml)，
依[政府資料開放授權條款－第1版](https://data.gov.tw/license)使用。
來源當時有 318 筆桃園登記資料；其中 294 筆具備 WGS84 座標而匯入地圖，另 24 筆未提供座標，列入待補清單。
座標直接使用來源值並做範圍檢查，未以地址猜測定位，也未逐筆現地查核。
原有雙北 15 筆示範資料及其照片、官網、設施與民俗欄位均保留。

## 資料維護

新增桃園資料的 `city` 為「桃園市」，`dist` 為地址所屬行政區；`sourceId` 保留內政部編號。
目前收藏、分享連結與集章以 `name` 識別宮廟，因此同名資料加註行政區；同區仍同名時加註地址，
原始登記名稱保留在 `sourceName`。更新時請依 `sourceId` 比對，避免任意改名造成既有連結失效。

電話只提供可辨識的完整主號；多組電話、分機或特殊標點經整理時，原值保留在 `sourceTel`。
缺少主祀神祇時保留空值。未經查證的設施、停車場、官網、照片與故事不填入。
兩筆官方登記若同址同座標但名稱及編號不同，仍保留各筆；匯入報告列出此情形。

更新時須同步修改 JSON 與 JS，並保留其他城市及既有人工補充欄位。
`convert_temples.py` 會重新產生資料檔，請勿直接以只含桃園的輸入覆蓋完整資料。

## 宮廟活動月曆（`?do=calendar`）

圖文選單「神明行事曆」與分享連結都開這個月曆。月曆日期格直接顯示宮廟照片、宮廟簡稱與活動短名；同日多項時格子只放一項代表，照片角落標「＋N」，點日期後下方列出當天全部活動卡片（大照片、宮廟、活動、時間、查看活動、導航過去）。

資料分三種，分開標示：

- **宮廟公告活動**：`data/events.json`，只放有來源的活動（目前為空）。以 `templeId` 對應宮廟：雙北 15 間用 `data/temples.json` 的 `id`（如 `tp-xingtian`），官方名冊資料用 `moi-<sourceId>`（如 `moi-1749886`）。有 `end` 就是多日活動；有 `lat`/`lng` 時導航到活動地點，否則導航至宮廟；有 `url` 時「查看活動」開網址，沒有就在月曆內展開已有資料。
- **神明誕辰**：`lunar.js` 的 `GOD_BIRTHDAY`，只配「主祀該神」的宮廟，時間一律「時間待確認」。
- **民俗節日**（初一、十五、中秋…）：只顯示文字，不配宮廟照片。

**示範模式**：`data/events-demo.json` 是比賽展示用的虛構活動（宮廟與照片是真的，活動是編的），只有按月曆底部「示範模式」或開 `?do=calendar&demo=1` 才載入，畫面全程標「示範活動」。真實資料裡標 `demo:true` 的項目一律不顯示。

照片只用該宮廟自己的 `photo`；沒有照片或載入失敗，顯示統一的小廟佔位圖，不拿別間廟的照片替代。

## 獅仔平安回報 Demo（`safety-demo.html`）

比賽展示用的純前端頁面，全程標示「展示模式：不會實際通知宮廟或派遣救援」。
沒有後端、沒有 LLM、沒有 LINE API、不需要登入或定位；情境與居民都是固定虛構資料。

- 入口：地圖篩選列的「平安回報」、直接開 `safety-demo.html`，或 `index.html?do=safety`（含 LIFF 的 `liff.state`）都會進 Demo。
- 居民端是「一次一題」的固定對話（獅仔問、按鈕答，畫面上方留已回答的紀錄，可按「修改」跳回任一題、「上一題」、「重新開始」）：
  1. 你現在平安嗎？→ 我平安／需要協助
  2. 位置 → 使用示範位置（固定虛構地址，標示「示範位置」）／手動輸入地址／暫不提供
  3. 協助需求（只有「需要協助」才問）→ 複選、至少一項，「其他」必填說明
  4. 人數（只有「需要協助」才問）→ 1／2／3／其他人數（1～50 的整數）
  5. 補充與聯絡方式 → 可略過；「填入示範資料」會帶入清楚標示為示範的內容
  6. 確認摘要 → 確認回報／返回修改
  7. 完成：「示範回報已記錄於本機」，可「複製回報內容」（只進剪貼簿，不會傳給任何人）、「模擬通知宮廟」（顯示「模擬通知完成，未實際發送」）、查看宮廟端、修改本次回報、重新開始。
- 只有按「確認回報」才會寫進本機紀錄與宮廟端統計；未確認的草稿另外存（`fuan.safetyDemo.draft.v2`），重新整理後會恢復到同一題，也不列入統計。
- 宮廟端：顯示詢問對象數、平安／需要協助／尚未回覆筆數、各項需求筆數、居民清單與待聯繫／已聯繫／已結案。
  「回報筆數」「需要協助人數」「各項需求筆數」三個數字分開算，不互相加總；宮廟端只是本機示範，不會和其他手機同步。
- 同一位居民（id `me`）永遠只有一筆：修改回報是更新原紀錄，不會多算一筆；由「需要協助」改成「我平安」時需求與人數一併清掉；
  已結案的居民再次確認求助會改回「待聯繫」。
- 資料只存在這支裝置的 `localStorage`（`fuan.safetyDemo.v2` 與草稿 `fuan.safetyDemo.draft.v2`），與收藏 `fuan.fav`、香火簿 `fuan.stamps` 分開；
  「重設全部示範資料」需確認，只清這兩個鍵（與舊版 `fuan.safetyDemo.v1`）。瀏覽器不能儲存時照常可以操作，畫面會提醒重新整理後會重設。
- 尚未做（下一階段）：真實定位（`navigator.geolocation`）與 LINE 分享給親友（LIFF `shareTargetPicker`）。這一版沒有任何會看起來像「已分享」的按鈕。
- 圖文選單「平安回報」設定為「連結」，網址填 `https://xup6jammy.github.io/fuan-map/safety-demo.html`。

## LINE 聊天室平安回報 Bot（`line-bot/`）

官方帳號聊天室裡的固定問答版（Quick Reply 一題一題問，不呼叫 AI 模型），是獨立的 Messaging API webhook 後端，
**不在 GitHub Pages 上**，要另外部署。流程、資料、配對與部署步驟見 `line-bot/README.md`。
測試：`cd line-bot && npm test`（LINE API 全部 mock）。

## 地圖驗看

透過 HTTP 伺服器開啟 `index.html`。允許定位後，地圖顯示定位點附近 5 公里內的宮廟，最多 60 筆；
人在台北時不會自動列出全部桃園宮廟。可到桃園使用定位，或以 `?temple=景福宮` 開啟指定宮廟。
新增宮廟資料不代表桃園的公廁、飲水機、YouBike、停車即時資訊也已補齊；這些是獨立資料來源。
